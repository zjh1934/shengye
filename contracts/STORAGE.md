# 存储布局（`:core:data` 唯一真源）

> 断点续跑能不能成立，八成取决于**文件怎么摆**。布局一改，已做好的块就对不上，
> 用户看到的是「明明做了一半，又说从头开始」。所以这份表先定死，代码照着写。

## 1. 根目录

一律用**应用私有目录**：`context.filesDir`（`/data/data/com.shengye.app/files`）。

不申请外部存储写权限——用户把 txt 从「文件管理」选进来时走 SAF（`ACTION_OPEN_DOCUMENT`）只读取一次，读完复制进私有目录。这样卸载即清干净，也不会被其他 App 乱动。

```
files/
├── prefs.json                     全局偏好（主题、默认参数、调音台、上次空间）
├── books/
│   └── <bookId>/
│       ├── source.txt             原文（导入时复制，此后只读）
│       ├── book.json              元数据 + 章节表 + 分块指纹
│       └── chunks/
│           └── c000/
│               ├── 0000.wav
│               └── 0001.wav       块音频，文件存在 = 这一块做完了
├── tasks/
│   └── <taskId>.json              任务快照（状态机写回的唯一落点）
├── audio/
│   └── <bookId>/
│       ├── c000.m4a               章成品（拼接 + 转码后）
│       └── c000.part.m4a          转码中间态，成功后删
├── clips/
│   └── <clipId>.m4a               片段（粘贴文本直接合成）
└── models/
    └── <slotId>/
        ├── model.onnx             或引擎要求的文件名
        └── slot.json
```

`<bookId>` / `<taskId>` / `<clipId>`：16 位十六进制随机串，导入时生成，**永不复用**。

## 2. 三个关键约定

### 2.1 「文件存在」就是「这块做完了」

不单独维护一张「完成表」。判断依据只有一条：`chunks/cXXX/NNNN.wav` 在不在。

理由：写文件和写数据库是两次 IO，中间被杀就会出现「库说做完了、文件其实是空的」。
用文件存在性当唯一判据，天然幂等，也不需要事务。

代价：写文件必须**先写临时名再改名**（`0001.wav.tmp` → `0001.wav`），否则半个文件也会被当成完成。

### 2.2 分块指纹，防止切法变了还硬续

`book.json` 里存：

```json
{
  "chunkRule": "v1-target120-max200",
  "chunks": [
    { "chapterIndex": 0, "index": 0, "chars": 118, "hash": "a3f1…" }
  ]
}
```

`hash` 是这一块**文本**的短哈希。续跑前逐块比对：
- 规则版本或块数变了 → 整体重排，已做的块全废（这是对的，切法都变了）
- 只有个别块 hash 变了（用户改过原文）→ 只重做那几块

### 2.3 成品与任务分开存

任务只记「做到哪了」，成品只记「哪些能听」。
删任务不删成品（音频是用户的资产），删成品不动任务（任务可能还要重做）。

## 3. 原子写

所有 json 一律：

```
写 xxx.json.tmp → fsync → rename 到 xxx.json
```

不做「直接覆盖写」。断电 / 被杀时宁可留下旧文件，也不要留下半个 json——
半个 json 会让 App 启动时解析失败，用户看到的是「书全没了」。

## 4. 清理策略（都要用户可见，不许偷偷删）

| 触发 | 删什么 | 不删什么 |
|---|---|---|
| 章转码成功 | 该章 `chunks/cXXX/` 下的 wav | 别的章 |
| 用户点「清理中间文件」 | 所有已转码章的 wav | 成品 m4a |
| 用户删书 | 整本 `books/<bookId>/` + `audio/<bookId>/` | 其他书 |
| 用户删成品 | 对应 m4a | 原文与块 |

**永不做**：按时间自动清理、按体积自动清理、「为了省空间」悄悄删。
用户的音频不是缓存。

## 5. 体积预估（写进设置页给用户看）

| 内容 | 量级 |
|---|---|
| 原文 | 1 万字 ≈ 30 KB |
| 块 wav（24kHz 单声道 16bit） | 每分钟 ≈ 2.8 MB |
| 章 m4a（64kbps 单声道） | 每分钟 ≈ 0.48 MB |
| 一本 10 万字中文（约 7 小时音频） | m4a ≈ 200 MB；中间 wav 峰值 ≈ 1.2 GB |

中间 wav 峰值大，所以**一章做完立刻清那一章的 wav**，账面占用就不会失控。
