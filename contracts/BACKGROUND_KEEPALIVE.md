# 后台保活与权限（`platform:service`）

> 用户要求：这个 App **非常耗电、吃 CPU、要长时间在后台跑**，必须把保活做扎实；权限该要的都要（文件读写、自启动、电池无限制、悬浮窗、通知等）；他自己会用权限管理软件给 App 放行。
> 参考：DeepSeek 安卓版的通行做法（前台服务 + 白名单引导 + 厂商自启动），不抄实现，只抄思路。

## 0. 为什么这个 App 特别吃后台

逐块合成是**几十分钟到几小时**的连续 CPU 任务（端侧 TTS，无网络），中途被系统杀掉就白做。所以保活不是"优化项"，是**核心功能的一部分**。

## 1. 保活梯级（由弱到强，逐级申请，不越级骚扰）

| 级 | 手段 | 何时用 | 用户感知 |
|---|---|---|---|
| L1 | **前台服务 + 常驻通知**（`FOREGROUND_SERVICE_DATA_SYNC` / `MEDIA_PROCESSING`） | 开始制作即启动 | 通知栏「声页 · 制作中」，可停止 |
| L2 | **`PARTIAL_WAKE_LOCK`** | 仅在合成进行时持有，结束立即释放 | 无感；**禁止常驻持锁** |
| L3 | **忽略电池优化**（`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`） | 首次开始制作前询问一次，拒绝不阻断 | 一次系统弹窗 |
| L4 | **厂商自启动 / 后台白名单引导** | 设置页「后台保活」一项，列出机型路径 | 一次性引导页 |
| L5 | **悬浮窗**（`SYSTEM_ALERT_WINDOW`） | 用户开启进度球时 | 屏幕上的双环数字 |
| L6 | **无障碍**（可选，默认关） | 仅用于"被系统清理后自动回到前台恢复" | 需用户手动开启，明确说明用途 |

**判据**：L1+L2 必须让合成在锁屏下持续跑完；L3–L6 是"更稳"，不是"必需"。任一级被拒，功能不残，只是更容易被系统回收 —— 回收后靠**断点续跑**兜底（已有，D1–D6）。

## 2. 权限清单（Manifest 声明）

| 权限 | 用途 | 备注 |
|---|---|---|
| `FOREGROUND_SERVICE` | 前台服务 | 必需 |
| `FOREGROUND_SERVICE_DATA_SYNC` | 合成任务类型（14+） | 必需 |
| `FOREGROUND_SERVICE_MEDIA_PROCESSING` | 音频处理类型（14+） | 必需 |
| `POST_NOTIFICATIONS` | 进度通知（13+ 运行时申请） | 必需 |
| `WAKE_LOCK` | 合成期间防休眠 | 必需 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 电池白名单 | L3 |
| `SYSTEM_ALERT_WINDOW` | 悬浮进度球 | L5，需用户手动授权 |
| `READ_MEDIA_AUDIO`（13+）/ `READ_EXTERNAL_STORAGE`（≤12） | 导入本机音频做参考音色 | 可选；导入书走 SAF 不需要 |
| `BIND_ACCESSIBILITY_SERVICE` | 可选保活辅助 | L6，默认关 |

**不声明 `INTERNET`** —— 离线是产品底线，也是保活省心的前提。

## 3. 厂商自启动引导（设置页那一项要写清楚路径）

| 厂商 | 路径 |
|---|---|
| 小米 / Redmi | 设置 → 应用设置 → 应用管理 → 声页 → 自启动 + 省电策略「无限制」 |
| 华为 / 荣耀 | 设置 → 应用 → 应用启动管理 → 声页 → 手动管理（自启动/关联启动/后台活动全开） |
| OPPO / 一加 / realme | 设置 → 电池 → 应用耗电管理 → 声页 → 允许后台运行 |
| vivo / iQOO | 设置 → 电池 → 后台高耗电 → 声页 → 允许 |
| 三星 | 设置 → 电池 → 后台使用限制 → 从「休眠应用」移除 |
| 原生 Android | 设置 → 应用 → 声页 → 电池 → 不受限制 |

> 引导页只列**当前机型**对应的一条，不铺六条（用户讨厌解释型文字）。

## 4. 红线（明确不做）

| 不做 | 原因 |
|---|---|
| 双进程守护 / 相互唤醒 / 1 像素 Activity 保活 | 黑产手段，耗电、被系统判定恶意、违反商店政策 |
| 常驻 WakeLock | 一夜掉 30% 电，用户会卸载 |
| 滥用无障碍（模拟点击、读屏） | 隐私红线；只做"回前台恢复"这一件事，且默认关 |
| 后台偷偷跑任务不通知 | 违反前台服务规范，也会被系统杀 |
| 申请 `MANAGE_EXTERNAL_STORAGE` | 过宽，SAF 足够 |

## 5. 被杀后的兜底（比保活更重要）

1. 每块 WAV 落盘即写 `seg.meta`，**已完成的不重做**。
2. 重启后读 `TaskResume`，按 `STATE_VOCAB §4` 的原因分卡（意外中断 → 「已做好的 N 块都留着 · 接着做」）。
3. 通知栏常驻一个「继续制作」入口，用户点一下即恢复。

## 6. 耗电与发热的产品化处理

- 设置页「后台保活」区显示：**本次已连续合成 N 分钟 · 耗电约 X%**（如果有 API 能取），让用户有预期。
- 提供「只在充电时合成」开关（默认关，开启后排队等待充电）。
- 合成中降低屏幕刷新无意义（不做 UI 动画），通知栏进度即可。

## 7. 验收（写进 `ACCEPTANCE.md` C 组）

- [ ] 锁屏 30 分钟，合成不中断（L1+L2）
- [ ] 强杀 App 后重启，已完成块不重做，续跑弹窗按原因分卡
- [ ] 拒绝电池白名单，仍能完成一次 10 分钟任务
- [ ] 关掉悬浮窗权限，进度球不显示但不崩
- [ ] 全程无 `INTERNET` 权限，断网可用
