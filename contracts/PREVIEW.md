# 界面出炉前的自查（强制）

> 起因：2026-11-15 用户装 alpha1 真机验收，一眼看出两个问题——
> **输入框太大**、**没考虑真机的状态栏和手势条**。
> 这两样在 HTML 设计稿里都"看着对"，因为设计稿压根没画系统栏。
>
> 结论：**不看到真机像素，就不知道做出来什么鸟样。** 这条适用于整个工程，不是某一张图。

## 一、硬流程（缺一步不算完成）

任何界面代码或设计图产出后，必须走完：

```
1. 画       → 用代码渲出真机尺寸（tools/shot.py）
2. 看       → 自己用视觉能力读这张图，逐条对照下面的检查表
3. 改       → 看过的问题当场改，改完重截
4. 再提交   → 图与代码同批提交
```

没截图的界面等于没做完。**不许**"我按设计稿写的，应该没问题"。

```bash
# 真机尺寸截图（默认 412×915 @2x，Pixel 7）
python3 tools/shot.py preview/real/home.html preview/real/home.png

# 截规格报告里的某一张
python3 tools/shot.py spec/index.html preview/real/spec_A1.png --sel '[data-id="A1"] .phone'
```

## 二、画的时候必须带系统栏

| 项 | 要求 |
|---|---|
| 状态栏 | 顶部真实占位（时间 / 信号 / 电量），高度约 24dp |
| 手势条 | 底部真实占位，约 16dp，`tab` 底色要铺到它底下 |
| 三键导航 | 底部约 48dp，比手势条高一倍——两种都要能看 |
| 挖孔 / 刘海 | 壁纸铺过去，内容避让 |

设计稿不画系统栏，等于默认"内容可以和系统 UI 抢位置"，真机上必翻车。

## 三、检查表（每次看图逐条过）

### 系统栏
- [ ] 顶栏第一行文字有没有压到状态栏的时间/电量
- [ ] 底部 tab 的文字有没有被手势条或三键导航盖住
- [ ] tab 底色有没有铺到屏幕最底（不能露一道壁纸缝）
- [ ] 深色主题下状态栏图标是不是浅色（否则看不见）

### 废话（用户最讨厌的）
- [ ] 页面大标题是不是和底部 tab 同名？同名就删
- [ ] 输入框上方有没有再写一遍"粘贴"之类的话？placeholder 已经说了
- [ ] 同一个动作有没有出现两个入口（卡片里一个、空态里又一个）？
- [ ] 正文有没有和标题说同一件事？
- [ ] 分组标题有没有和顶栏同名？
- [ ] 页面里有没有讲解性段落（"点击这里可以…"）？一律删

### 比例
- [ ] 输入框高度是不是按屏幕比例撑的？必须固定值（约 72dp）
- [ ] 主要动作和次要动作之间有没有隔一大片空白？有就收进同一张卡
- [ ] 列表是不是一个列表每行套一张卡？必须一张卡包多行
- [ ] 一屏有几个主按钮？超过一个就没有主次

### 状态
- [ ] 每个可见状态都能在 `STATE_VOCAB.md` 里找到词
- [ ] 一屏只有一根进度条、一个百分比
- [ ] 空态是"状态 + 下一步"，不是教程

## 四、落点

| 产物 | 位置 |
|---|---|
| 真机尺寸预览（HTML 真源） | `preview/real/*.html` |
| 真机尺寸预览（截图，入库） | `preview/real/*.png` |
| 截图工具 | `tools/shot.py` |
| 规格报告（65 张形态图） | `spec/index.html`（`python3 spec/build.py` 生成） |

`spec/` 是给子智能体看的结构参考，`preview/real/` 是做出来长什么样。
**两个都要看，只看一个会偏。**

## 五、几何口径

设计稿基准宽 268px ↔ 真机 412dp，换算比例 **1.54**。
规格里的 `min-height:47px` 就是真机的 72dp。改规格尺寸时按这个比例算，
不要凭感觉给数字——`GLASS_TOKENS.md` §2 是唯一口径。
